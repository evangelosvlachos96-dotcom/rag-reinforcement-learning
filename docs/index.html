rag-reinforcement-learning

Multi-armed bandits that learn which RAG retrieval configuration to use, rewarded by the retrieval metrics of the agentic-rag-eval-platform library.

Source code RAG library

The problem

A RAG system has settings that change answer quality: how the corpus is chunked, and how many retrieved chunks reach the generator. Choosing them by hand means guessing or running a full grid. Here each combination is an arm of a bandit, the retrieval quality (nDCG@k) on a query is the reward, and a policy learns which arm to favour while still exploring the rest. This is the simplest reinforcement learning setting: a stateless bandit.

Setup

9 arms: chunk size 200, 400 or 800 tokens, crossed with context size k = 4, 8 or 16.
Reward: binary-relevance nDCG@k on the 20 answerable questions of the RAG library's v1 eval set, using BM25 retrieval over the pinned PEP corpus (56 documents).
Policies: random baseline, epsilon-greedy (ε = 0.1), and UCB1, all implemented from scratch.

What the results do not show

The best arm is not statistically established. chunk800_k16 leads the runner-up by 0.022 nDCG. A paired bootstrap over the 20 queries gives a 95% interval of −0.018 to +0.065, which includes zero.
The held-out check is small. Ten training and ten test queries. The policies picked the same arm that was best on the test half, but that is too few queries to say much.
The reward measures retrieval, not answers. nDCG@k favours larger k by construction. Answer faithfulness, generation cost and latency are not measured.
No vector or hybrid arms. Those need an embedding model download that was not reachable where this was built, so every arm is BM25.

(cd ../agentic-rag-eval-platform && uv run rag download-corpus)

uv run rl-rag-simulate
